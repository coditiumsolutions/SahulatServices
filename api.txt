POST Send OTP
--------------------------------------------------------------------------------
Local:     https://localhost:7265/api/auth/send-otp
Deployed:  https://sahulatghartak.com/api/auth/send-otp

Request Body:
{
  "mobileNo": "03001234567",
  "otpType": "Registration"
}

Notes:
- otpType: Registration | Login | PasswordReset
- Mobile format: 03XXXXXXXXX (optional +92 prefix normalized)
- OTP is 6 digits; ExpiryTime = now + 5 minutes
- Unverified OTP for same mobile+type is updated (not duplicated)
- Registration: if mobile already exists and IsVerified=true -> 409
- data.otp is controlled by config Otp:IncludeInResponse (true = include code; false = null)
- TEMPORARY: IncludeInResponse=true on deployed API until a real SMS gateway is wired; then set false

Success (200 when Otp:IncludeInResponse=true):
{
  "success": true,
  "message": "OTP sent successfully.",
  "data": {
    "mobileNo": "03001234567",
    "otpType": "Registration",
    "expiryTime": "2026-07-20T16:40:00",
    "otp": "458963"
  }
}

Success (200 when Otp:IncludeInResponse=false):
{
  "success": true,
  "message": "OTP sent successfully.",
  "data": {
    "mobileNo": "03001234567",
    "otpType": "Registration",
    "expiryTime": "2026-07-20T16:40:00",
    "otp": null
  }
}

Fail (400):
{
  "success": false,
  "message": "Invalid mobile number format. Use 03XXXXXXXXX.",
  "data": null
}

Fail (409):
{
  "success": false,
  "message": "Mobile number already registered.",
  "data": null

POST Verify OTP
--------------------------------------------------------------------------------
Local:     https://localhost:7265/api/auth/verify-otp
Deployed:  https://sahulatghartak.com/api/auth/verify-otp

Request Body:
{
  "mobileNo": "03001234567",
  "otp": "458963"
}

Notes:
- Uses latest unverified OTP for the mobile number
- Max 3 invalid attempts (AttemptCount)
- On success: UserOTP.IsVerified=true, VerifiedOn set
- If UsersLogin row exists: UsersLogin.IsVerified=true

Success (200):

  "success": true,
  "message": "OTP verified successfully.",

    "isVerified": true,
    "userVerified": true

POST Resend OTP
--------------------------------------------------------------------------------
Local:     https://localhost:7265/api/auth/resend-otp
Deployed:  https://sahulatghartak.com/api/auth/resend-otp

Request Body:
{
  "mobileNo": "03001234567",
  "otpType": "Registration"
}

Notes:
- Generates a new 6-digit OTP
- Resets AttemptCount to 0
- Refreshes ExpiryTime (+5 minutes)
- Increments SentCount (max 5)
- Sends via ISmsService (DummySmsService logs to console)
- data.otp follows Otp:IncludeInResponse (same as send-otp)

Success (200 when Otp:IncludeInResponse=true):
{
  "success": true,
  "message": "OTP resent successfully.",
  "data": {
    "mobileNo": "03001234567",
    "otpType": "Registration",
    "expiryTime": "2026-07-20T16:45:00",
    "otp": "781204"
  }
}

Fail (429):
{
  "success": false,
  "message": "Maximum OTP resend limit reached. Try again later.",
  "data": null
}

GET Provider Wallet (balance + transaction history)
--------------------------------------------------------------------------------
Local:     https://localhost:7265/api/providers-wallet/{providerUid}
Deployed:  https://sahulatghartak.com/api/providers-wallet/{providerUid}

Example:
GET https://localhost:7265/api/providers-wallet/4

Request Body: none

Notes:
- Balance reflects the provider's running PaymentLedger balance: positive means the
  company owes the provider (unpaid online-job earnings); negative means the provider
  owes the company (commission on cash-to-provider jobs collected but not yet remitted).
- A cash job immediately posts a "JobEarning" credit (provider's share after commission)
  and a "CashCollect" debit (full cash amount collected), netting to -commission owed.
- pendingPayoutTotal is the sum of admin-payable ProviderPayout rows (Status=Pending),
  created for OnlineToCompany jobs where the company holds the money and owes the provider.
- Admin triggers actual payouts manually from the admin portal (Person Ledger > Pay Now),
  which nets the payout against any outstanding negative balance automatically.
- transactions are most-recent-first; signedAmount: Credit = +, Debit = −.

Success (200):
{
  "success": true,
  "message": "Provider wallet fetched successfully.",
  "data": {
    "providerUid": 4,
    "providerName": "Ryyan",
    "categoryName": "Carpenter Services",
    "balance": -100.00,
    "pendingPayoutTotal": 0.00,
    "transactions": [
      {
        "uid": 6,
        "createdOn": "2026-07-15T12:21:30.78",
        "bookingUid": 5,
        "reason": "CashCollect",
        "signedAmount": -1000.00,
        "runningBalance": -100.00
      },
      {
        "uid": 5,
        "createdOn": "2026-07-15T12:21:30.78",

POST Respond To Booking (Provider Accept/Reject)
--------------------------------------------------------------------------------
Local:     https://localhost:7265/api/service-bookings/{bookingUid}/respond
Deployed:  https://sahulatghartak.com/api/service-bookings/{bookingUid}/respond

Example:
POST https://localhost:7265/api/service-bookings/1/respond

Request Body:
{
  "providerUid": 4,
  "accept": true
}

Notes:
- booking must belong to providerUid and currently be Status="Pending" (i.e. staff-assigned,
  awaiting provider response)
- accept:true -> Status="Accepted", AcceptedOn set, a 4-digit Passcode is generated and
  returned to the client so the app can display it in booking details
- accept:false -> Status="Rejected" (staff-only; hidden from all client/provider-facing
  responses), and the parent CustomerServiceRequest reverts to Status="Pending" so staff
  can reassign a different provider

POST Verify Completion Passcode (Provider marks job Completed)
--------------------------------------------------------------------------------
Local:     https://localhost:7265/api/service-bookings/{bookingUid}/verify-completion
Deployed:  https://sahulatghartak.com/api/service-bookings/{bookingUid}/verify-completion

Example:
POST https://localhost:7265/api/service-bookings/1/verify-completion

Request Body:
{
  "providerUid": 4,
  "passcode": "4821",
  "actualAmountPaid": 3000,
  "paymentMode": null
}

Notes:
- booking must belong to providerUid and currently be Status="Accepted" or "In Progress"
- passcode must match the client-visible Passcode generated at accept time
- actualAmountPaid is the real amount collected at job completion; it overwrites
  CustomerPaid and CustomerRemaining is recomputed (FinalAmount - actualAmountPaid) —
  supports partial payment (CustomerRemaining stays > 0)
- paymentMode is OPTIONAL; pass CashToProvider or OnlineToCompany only if it changed from
  what staff set at assignment time, otherwise omit/null to keep the existing value
- on success: Status="Completed", CompletedOn set, CustomerServiceRequests.Status synced to
  "Completed", and PaymentLedger/ProviderPayouts entries are posted automatically based on
  the final PaymentMode + CustomerPaid (handles cash-to-provider, online-to-company, and
  partial payment cases)

Success (200):
{
  "success": true,
  "message": "Booking marked as completed successfully.",
  "data": {
    "uid": 1,
    "status": "Completed",
    "customerPaid": 3000.00,
    "customerRemaining": 0.00,
    "completedOn": "2026-07-20T14:30:00",
    "...": "remaining fields same shape as GET Booking By Id"
  }
}

Fail (400 - wrong passcode):
{
  "success": false,
  "message": "Incorrect passcode.",
  "data": null
}

Fail (400 - wrong state):
{
  "success": false,
  "message": "This booking is not awaiting completion.",

================================================================================
SERVICE TITLES APIs
================================================================================
Hierarchy: Services -> ServiceCategories -> ServiceTitles
Flutter flow: GET /api/service-categories?serviceUid={id} then GET /api/service-titles?categoryUid={id}

--------------------------------------------------------------------------------
GET All Service Titles
--------------------------------------------------------------------------------
Local:     https://localhost:7265/api/service-titles?categoryUid={id}
Deployed:  https://sahulatghartak.com/api/service-titles?categoryUid={id}

Required Query:
- categoryUid (int) — parent service category

Example:
GET https://localhost:7265/api/service-titles?categoryUid=1

Request Body: none

Success (200):
[
  {
    "id": 1,
    "categoryId": 1,
    "categoryName": "Plumber",
    "title": "Leak Repair",
    "description": "Fixing pipe and faucet leaks",
    "displayOrder": 1,
    "createdOn": "2026-08-06T00:00:00"
  }
]

Fail: returns empty array [] when no active titles found
